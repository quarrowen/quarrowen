Quarrowen

Run a world for your people.

Start a world and everyone you invite just clicks Join. The world brings the game with it - its blocks, creatures, rules, whole games - so there are no mod folders, no accounts, and nothing to keep in step between friends. Free, for Mac and Windows.

Download for Mac {{version}} · {{mac_size}} {{win_cta}} Host a world →

Sent here by a friend? Download it, open it and choose Multiplayer. On the same network as them, their world is already in the LAN list; otherwise paste the address or invite code they sent you into the box at the top and press Join.

On a Mac: download it, drag it to Applications, and open it. It is signed and notarised, so there is no warning box to click past, and it keeps itself up to date. Intel and Apple silicon both.

One app, every world

Same app. Three worlds. Nothing installed in between. Each world on a server runs its own game, so you can walk through a portal out of a survival world and into a fairground of short games, and the app becomes that game on the way through.

What comes with it

All four come in the download. Play one on your own, or run them side by side on a server and let your people walk between them. The Fairground is the one to start a group evening on.

Host a world

You bring the people and the server brings the game. All of this is true whether the world is for a family, a group of friends, or a class.

Only the people you allow

A world lets in the names on its list and nobody else, and that permission carries across every world you run, so nobody is stopped halfway through a portal.

No accounts anywhere

No sign-up, no email, no telemetry. A player is a key on their own computer, and nothing is sent anywhere except the server they chose to join.

The server sends data, never code

There is no mod runtime in the app at all. What a server may send is checked and size-limited before anything is done with it.

Security →

Your worlds are files on your machine

Back them up, move them between machines, keep them. Nothing about a world lives anywhere you cannot reach.

What it takes

A spare Linux machine with Docker is enough. Three worlds and a hub, running side by side, in about ten minutes.

QW_IMAGE=ghcr.io/quarrowen/quarrowen/server:{{version}}
QW_HUB_IMAGE=ghcr.io/quarrowen/quarrowen/hub:{{version}}

docker compose pull && docker compose up -d

Players in the same house find the world by themselves. Players somewhere else need you to open a port on your router first, or to put everybody on one private network - that is the part of hosting this cannot do for you. Hosting →

Make something

Anything a bundled game does, yours can do. Blocks, creatures and their behaviour, world generation, machines, crafting, whole games - in GDScript, or in JavaScript that runs in a sandbox. Put it on your server and everyone gets it the next time they join.

const ruby = api.registerBlock("ruby_ore", { textures: "textures/ruby.png", light: 5 });
api.addOrePass({ ore: "my_mod:ruby_ore", veins: 2, min_y: 5, max_y: 30 });
api.on("block_broken", ({ player, block }) => {
  if (block === ruby) player.showTitle("Shiny!");
});

Written once, kept working. Mods call the mod API and never the engine's insides, and the API only grows: a function never changes in place, and an old name keeps working until a major version.

Where it came from

I built it for my kids and their friends: a world they could all join without anybody sorting out files first. It grew from there.

Every line of it was written with Claude Code, from an empty folder - the renderer and its Rust mesher, the server and its protocol, creature behaviour, the mod API and its sandbox, world generation, the tests and the tooling. No engine template: the textures, models and music are made by scripts, and the sound effects are CC0 and credited. The decisions and the bugs are written down as they happen, in PROGRESS.md, and the bugs are mostly more interesting than the features.
