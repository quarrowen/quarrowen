## Done on `mob-ai` (engine mob AI)

- `native/src/pathfind.rs`: size-aware voxel A* (width x height footprint, step_up, max_drop,
  swimming, hazard blocks, edge avoidance, partial paths), walkable-line and line-of-sight checks;
  bound on `NativeVoxelWorld` (`find_path`, `walkable_line`, `standable`, `line_of_sight`,
  `set_ai_tables`). Batched `step_entities` for entity physics (from `gameplay`).
- `engine/server/ai/`:
  - `pathfinder.gd` — native wrapper + identical GDScript fallback (smaller node budget).
  - `mob_config.gd` — presets (hostile, neutral, passive, archer, boss, wander, none) + overrides:
    aggression, courage, intelligence, agility, senses, memory, group/enemy_groups, alerts, leash,
    step_up/max_drop/can_swim, attacks, phases, boss bar, custom behaviors.
  - `mob_brain.gd` — perception (FOV + LOS + hearing noises), memory/last-known position, threat
    tables, utility behavior selection (idle, wander, investigate, engage, search, flee,
    return_home, scripted, custom), path following with string-pulling, jumping, separation,
    surround slots, ranged kiting/strafing, projectile dodging, stagger on heavy hits, out-of-combat
    recovery, boss phases.
  - `mob_attacks.gd` — telegraphed attacks: melee (arc), ranged (leads targets, gravity arc),
    leap, charge (stuns on walls), slam (AoE), summon, custom (`mob_attack` event).
  - `mob_ai.gd` — manager: path request budget, spatial grid, noises, ally alerts, surround slots,
    boss bars, projectile awareness.
- Integration: entities attach brains to `kind: "mob"`; noises from block breaks/places, attacks,
  damage, sprinting, projectile hits; block `hazard` flag; entity height up to 16 / width 8;
  `damage_player(..., knockback)`; client wind-up/attack animations (events 3 and 5); server UI
  progress bars accept `color`/`width`.
- Mod API: `register_mob_behavior`, `make_noise`, entity methods `set_target`, `get_target`,
  `add_threat`, `tune`, `alert`, `set_home`, `perform_attack`, `get_behavior`, `set_goal`;
  events `mob_target`, `mob_attack`, `mob_phase`. JavaScript equivalents in `js_mod.gd`,
  `js/prelude.js`, `js/voxelcraft.d.ts` (`registerMobBehavior`, `makeNoise`, `mob.tune`, ...).
- Content: vanilla zombie (pack hunter with claw + lunge), skeleton archer (kites, strafes, dodges,
  arrows), pigs (herd alerts), Ancient Colossus boss (`/colossus`, 1.2 wide x 7.2 tall, stomp/punch,
  phase 2 charge + raise dead, boss bar); guild JS: elite bounty via `tune`, treasure goblin with a
  JavaScript mob behavior (`/guild goblin`). New models/sounds/textures generated by tools.
- Tests: `tests/ai_test.tscn` + `tests/mods/ai_arena` (pathfinding, perception, chase, dodgeable
  wind-ups, surround, archer range, flee/threat, ally alert, boss phases/summons, giant, custom
  behavior, tuning, dodging, JS behavior); wired into `tools/run_tests.sh`. Combat e2e sprints now.
- Benchmark (`tests/bench.tscn`): 300 mobs (≈130 hunting 10 players) + 200 items ≈ 3.5 ms/tick
  native, ≈ 9.3 ms/tick GDScript fallback.

## Next feature discussed: equipment (user request, not started)

User wants: vanilla ships basic armor, weapons and tools, but mods define everything — including
progression (items that level up with use), upgrades, and engine-provided visual/audio effects
(glows, trails, particles, sounds) that mods attach to weapons/armor/tools. Design to propose:

- Item instances with per-stack data (durability, xp/level, upgrades, enchant-like modifiers)
  instead of plain id+count stacks; inventory/network/save format changes.
- Equipment slots (head, chest, legs, feet, offhand, accessories defined by mods) and a stat system
  (armor, toughness, attack damage/speed, mining speed/tier, movement modifiers) with modifiers from
  items and effects; damage pipeline uses them.
- Tools: mining speed/tier vs block hardness (blocks need hardness/tool type), durability.
- Weapons: melee (reach, arc, cooldown, crits, sweep), ranged (bows/wands via projectiles), abilities.
- Progression hooks: events on use/kill/block mined, per-item xp curves, upgrade recipes/UI.
- VFX/SFX engine capabilities (data-driven, client-rendered, no mod code on client): held-item and
  armor models with glow/emissive, weapon trails, hit sparks, particle emitters (spec: texture,
  count, lifetime, velocity, color ramp, gravity), screen effects, attached to item definitions or
  triggered via API (`play_effect`), plus sound hooks (swing, hit, equip, break).
- Client: first-person held item rendering, third-person equipment on player models.
